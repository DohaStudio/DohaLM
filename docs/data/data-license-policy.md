## 2. 기본 원칙

- [확정] 데이터 사용 전에 제공자, 공식 출처, version, 이용조건과 적용 목적을 확인한다.
- [확정] 출처 또는 라이선스가 불명확한 데이터는 학습과 토크나이저 corpus에서 제외한다.
- [확정] 접근 가능하다는 사실을 학습·수정·재배포·모델 공개 허가로 해석하지 않는다.
- [확정] 원본 데이터 공개 허용과 파생 모델 weight 공개 허용을 별도 항목으로 검토한다.
- [확정] 사용조건이 목적별로 다르면 토크나이저, 사전학습, SFT, 평가와 공개를 각각 기록한다.

## 3. 사용 전 확인 절차

| 순서 | 확인 내용 | 필수 기록 | 불명확할 때 |
|---:|---|---|---|
| 1 | 공식 제공자와 원천 version 식별 | provider, source URL, version | `candidate` 유지 |
| 2 | 라이선스 원문·공식 이용조건 확보 | license명, 공식 링크 또는 보관 위치 | 사용 중단 |
| 3 | 취득 시점의 조건 보존 | 취득일·검토일·조건 snapshot 식별자 | 재현 가능한 보존 방법 [검증 필요] |
| 4 | 모델 학습·토크나이저 학습 허용 검토 | 목적별 허용·금지·조건 | `[법률 검토 필요]` |
| 5 | 상업적 이용 여부 확인 | allowed/prohibited/conditional/unknown | `unknown`을 허용으로 보지 않음 |
| 6 | 정제·변형 가능 여부 확인 | modification 조건 | 불명확하면 처리 금지 |
| 7 | 원본·정제본 재배포 여부 확인 | redistribution 조건 | 불명확하면 재배포 금지 |
| 8 | 파생 모델 공개 가능성 확인 | weight·tokenizer 공개 조건 | `[법률 검토 필요]` |
| 9 | 출처 표시와 고지 의무 확인 | 문구·위치·범위 | 이행 방법 확정 전 공개 금지 |
| 10 | 개인정보·삭제·접근 제한 확인 | 위험·삭제 contact·보관 조건 | 승인 보류 |
| 11 | 검토자와 근거 기록 | owner·결정·날짜·notes | 승인 불가 |

## 4. 조건별 기록 기준

### 4.1 상업적 이용

- [확정] `commercial_use`를 `allowed`, `prohibited`, `conditional`, `unknown`으로 구분한다.
- [검증 필요] 프로젝트의 향후 공개·포트폴리오·서비스 형태가 조건상 상업적 이용에 해당하는지는 상황별 검토가 필요하다.

### 4.2 수정과 재배포

- [확정] normalization, 필터, 포맷 변환, 중복 제거도 수정 가능 여부와 관련될 수 있으므로 기록한다.
- [확정] 수정 가능하더라도 원본·정제본·소형 표본의 재배포 가능 여부는 따로 확인한다.
- [확정] 재배포가 금지되면 데이터 본체를 Git·모델 패키지·공개 산출물에 포함하지 않는다.

### 4.3 파생 모델과 토크나이저 공개

- [검증 필요] 학습된 model weight가 이용조건상 파생물에 해당하는지, 공개에 추가 의무가 있는지는 데이터셋별로 검토한다.
- [검증 필요] SentencePiece `.model`·`.vocab` 공개가 corpus의 정보를 노출하거나 조건의 영향을 받는지 별도 검토한다.
- [법률 검토 필요] 조건 문구가 모델·토크나이저 공개에 관해 명시적이지 않고 해석에 따라 결과가 달라지는 경우 외부 검토 전 공개하지 않는다.

### 4.4 출처 표시

- [확정] attribution이 필요하면 요구 문구, 링크, 저작자, 라이선스와 표시 위치를 registry에 기록한다.
- [확정] 여러 데이터셋을 혼합하면 각 의무를 잃지 않도록 모델 카드의 데이터 출처 표와 연결한다.

## 5. 이용조건 변경 대응

1. [확정] 정기 검토 또는 재사용 전에 공식 조건의 현재 version을 확인한다.
2. [확정] 변경일·발견일·이전 조건·신규 조건과 영향 범위를 기록한다.
3. [확정] 신규 사용이 불명확하면 데이터 상태를 `deprecated` 또는 재검토 상태로 전환하고 새 학습을 중단한다.
4. [검증 필요] 기존 checkpoint·tokenizer·모델 공개에 미치는 영향과 철회 필요성을 검토한다.
5. [법률 검토 필요] 소급 적용 여부나 기존 파생물 처리에 해석이 필요하면 임의로 결론 내리지 않는다.

## 6. 데이터 삭제 요청 대응

- [확정] 요청의 대상, 권한, dataset ID, 원본 ID와 적용 범위를 확인한다.
- [확정] 원본→정제→split→token shard→실험·checkpoint의 계보를 조회해 영향 범위를 기록한다.
- [확정] 보존 의무와 권한을 확인한 뒤 승인된 절차로 원본과 재생성 가능한 파생 데이터를 처리한다.
- [검증 필요] 이미 학습된 checkpoint와 공개 모델에 대한 대응은 기술적·법적 가능성을 함께 검토한다.
- [법률 검토 필요] 삭제 의무와 보존 의무가 충돌하거나 model weight 영향 판단이 필요한 경우 별도 검토한다.
- [확정] 삭제 결과, 처리하지 못한 범위, 근거와 후속 재학습 필요성을 기록한다.

## 7. 특수 출처 정책

### 7.1 웹 크롤링 데이터

- [확정] 공개 웹 접근 가능 여부만으로 사용을 승인하지 않는다.
- [검증 필요] 사이트 이용약관, robots 관련 신호, 저작권, 개인정보, 접근 방식과 재배포 조건을 출처별로 검토한다.
- [확정] 이번 단계에서는 웹 크롤링을 수행하지 않으며 향후 별도 승인·수집 정책 없이는 사용하지 않는다.
- [법률 검토 필요] 대규모 수집과 학습 허용 범위가 불명확하면 제외한다.

### 7.2 AI Hub 데이터

- [확정] 데이터셋별 이용조건, 신청 계정, 다운로드·보관·제3자 제공·성과물 공개 조건을 당시 공식 문서에서 별도 확인한다.
- [확정] AI Hub라는 제공처만으로 모든 데이터셋에 동일 조건이 적용된다고 가정하지 않는다.
- [검증 필요] 토크나이저·model weight·평가 결과 공개 및 K-AI Leaderboard 제출과의 조건 호환성을 해당 시점에 확인한다.
- [확정] 이번 단계에서는 AI Hub 데이터를 다운로드하거나 특정 데이터셋을 승인하지 않는다.

## 8. 모델 카드 기록 기준

모델을 공개하거나 배포 후보로 만들 때 다음을 기록한다.

- [확정] 사용한 데이터셋 이름·version·provider와 목적
- [확정] 공개 가능한 공식 출처·라이선스 링크와 attribution
- [확정] 원본을 재배포하지 않는다는 경계와 접근 제한
- [확정] 주요 정제·필터·중복 제거·분할 방식과 version
- [확정] 알려진 개인정보·유해성·편향·누수 위험과 제한
- [확정] 데이터셋별 공개 조건이 모델 사용·재배포에 미치는 제한
- [검증 필요] 공개할 수 없는 데이터의 투명성을 어느 수준으로 제공할지 조건별로 결정한다.

## 9. 미결정 및 검토 필요 사항

- [검증 필요] 실제 후보 데이터와 공식 이용조건
- [검증 필요] 조건 원문 snapshot의 보관 형식과 갱신 주기
- [법률 검토 필요] 파생 모델과 tokenizer 산출물 공개가 불명확한 조건
- [법률 검토 필요] 삭제 요청이 기존 checkpoint·공개 모델에 미치는 영향
- [검증 필요] 승인 책임자와 법률 검토 escalation 절차
