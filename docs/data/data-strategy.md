## 2. 데이터 전략 원칙

- [확정] 출처와 라이선스를 확인할 수 없는 데이터는 토크나이저·사전학습·SFT·평가에 사용하지 않는다.
- [확정] 원본은 불변으로 보존하고 정제·분할·토큰화 결과는 버전이 있는 별도 산출물로 만든다.
- [확정] 데이터셋 ID, 원본 checksum, 전처리 버전, 분할 버전과 소비 실험을 연결한다.
- [확정] 토크나이저, 사전학습, SFT와 평가는 목적 및 허용 누수 범위가 다르므로 논리적으로 분리한다.
- [확정] 승인 상태는 데이터셋 전체의 추상적 평판이 아니라 특정 버전·라이선스·사용 목적 조합에 부여한다.
- [확정] 실제 학습 전 개인정보, 민감정보, 유해 콘텐츠, 저작권과 평가 오염 위험을 기록한다.
- [확정] Phase 1 구현에 직접 적용할 입력·schema·checksum·manifest·정규화·exact dedup·split 계약은 [Phase 1 데이터 계약](./phase1-data-contract.md)을 단일 기준으로 사용한다.

## 5. 후보와 승인 데이터 상태

| 상태 | 의미 | 진입 조건 | 다음 가능한 상태 |
|---|---|---|---|
| `candidate` | 출처가 식별된 검토 후보 | registry 최소 식별 정보 기록 | `reviewing`, `rejected` |
| `reviewing` | 라이선스·품질·위험을 검토 중 | 공식 조건과 표본 접근 가능 | `approved`, `rejected` |
| `approved` | 특정 버전과 목적에 사용 승인 | 라이선스·품질·위험·누수 검토 완료 | `downloaded`, `deprecated` |
| `rejected` | 현재 목적에 사용하지 않음 | 불명확한 권리 또는 기준 미달 사유 기록 | 재검토 시 `reviewing` |
| `downloaded` | 승인된 원본을 취득하고 checksum 기록 | 승인 범위·취득 절차 준수 | `processed`, `deprecated` |
| `processed` | 승인된 전처리·분할 버전 산출 | manifest·통계·품질 검사 완료 | 소비 또는 `deprecated` |
| `deprecated` | 신규 사용 중단 | 조건 변경·대체·오류 사유 기록 | 필요 시 새 version을 `candidate`로 등록 |

- [확정] `downloaded`와 `processed`는 품질 승인을 대신하지 않으며 반드시 `approved` 이후에만 사용할 수 있다.
- [확정] 라이선스가 불명확하면 `approved`로 전환하지 않는다.
- [확정] 후보 등록부에는 5개가 `registered`이나 실제 dataset registry version과 `approved` 목적은 0개다.

## 6. 단계별 데이터 규모

| 단계 | 목적 | 데이터 범위 | 종료 조건 | 규모 상태 |
|---|---|---|---|---|
| 파이프라인 검증용 극소량 데이터 | 입출력·오류·계보 확인 | 허가된 소형 표본 또는 synthetic fixture | 전체 단계와 manifest 연결 확인 | [검증 필요] 수치 미정 |
| 토크나이저 실험용 표본 | 문자 통계와 Unigram 후보 비교 | 승인 corpus의 재현 가능한 표본 | coverage·normalization·fallback 비교 가능 | [검증 필요] 수치 미정 |
| 단일 배치 과적합 데이터 | loss·mask·checkpoint 검증 | 고정된 소형 token block | 의도적 과적합과 복원 성공 | [검증 필요] 수치 미정 |
| Tiny 소규모 사전학습 데이터 | pilot 학습과 처리량 검증 | 승인·분할된 한국어 문서 | loss·평가·OOM 흐름 검증 | [검증 필요] token budget 미정 |
| Tiny 확장 사전학습 데이터 | 품질 개선 가능성 평가 | 더 넓은 승인 데이터 | pilot 통과와 자원 계획 승인 | [검증 필요] token budget 미정 |
| SFT 검증 데이터 | 템플릿·loss mask·응답 변화 확인 | 승인된 소형 Q/A·대화 | SFT 전후 고정 평가 가능 | [검증 필요] 수치 미정 |
| Small 검토용 데이터 | Tiny 결과 기반 확장성 판단 | Tiny와 계보가 연결된 승인 데이터 후보 | Small 사양·비용 재검토 | [후순위], 수치 미정 |

- [확정] 단계 확대는 단순 문서 수가 아니라 데이터 승인, 처리 품질, token 통계와 `RTX 3060 Ti 8GB` 처리량을 함께 근거로 한다.
- [검증 필요] 정확한 문서 수, byte 크기, 표본 비율과 token budget은 실제 registry와 pilot 결과로 결정한다.

## 7. 승인 절차

1. [확정] 후보를 [데이터셋 레지스트리](./dataset-registry.md)에 `candidate`로 등록한다.
2. [확정] 공식 라이선스·이용조건과 취득일을 기록하고 [라이선스 정책](./data-license-policy.md)에 따라 검토한다.
3. [확정] 접근이 허용된 표본으로 품질·개인정보·유해성·누수 위험을 평가한다.
4. [확정] 사용 목적별 허용 범위와 필요한 출처 표시·삭제 대응을 기록한다.
5. [확정] 승인 책임자가 근거를 검토해 `approved` 또는 `rejected`로 전환한다.
6. [확정] 승인 이후에만 취득·전처리를 수행하고 checksum, manifest와 통계를 연결한다.
7. [확정] 이용조건이나 데이터가 바뀌면 기존 version을 재검토하거나 `deprecated`로 전환한다.
