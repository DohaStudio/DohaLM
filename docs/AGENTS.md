# DohaLM 문서 작업 규칙

이 파일은 `docs/` 아래 문서 작업에 적용되며 루트 [저장소 작업 규칙](../AGENTS.md)을 구체화한다.

## 1. 작성 원칙

- 모든 기준 문서는 한국어 Markdown으로 작성한다.
- 기준 문서 상단에 문서 상태와 마지막 검토일을 기록한다.
- 본문 중요 항목은 `[확정]`, `[가정]`, `[검증 필요]`, `[후순위]`, `[제외]`로 구분한다.
- 문서 생명주기 상태와 본문 상태 태그를 혼동하지 않는다.
- 구현되지 않은 기능, 실행하지 않은 테스트, 생성하지 않은 릴리스를 완료로 표현하지 않는다.
- 확인되지 않은 수치·설정·성능·일정을 임의로 만들지 않는다.
- 동일 내용을 복제하기보다 현재 기준 문서와 ADR에 상대 링크로 연결한다.
- 외부 최신 규정·API·Leaderboard 정보를 적용할 때는 적용 시점의 공식 출처를 다시 확인한다.
- 요청 대상 외 문서를 대규모로 수정하지 않는다.

## 2. 링크와 인덱스

- 존재하지 않는 예정 파일은 Markdown 링크가 아닌 코드 표기로 작성한다.
- 문서를 생성하거나 상태·선후 관계를 변경하면 [문서 인덱스](./index.md)를 동기화한다.
- ADR을 생성·변경하면 [ADR 인덱스](./decisions/README.md)를 동기화한다.
- 의미 있는 변경에는 문서 하단 변경 이력을 추가한다.

## 3. 문서 상태 변경

- `planned → draft`는 실제 초안 작성 시, `draft → review`는 필수 항목과 검증 결과 작성 시에만 가능하다.
- `review → approved`는 사용자 승인 또는 명시적 승인 지시가 있을 때만 가능하다.
- `approved → implemented`는 코드·설정·테스트 반영과 검증 완료 후에만 가능하다.
- `deprecated`는 후속 ADR 또는 사용자 결정이 있을 때만 가능하다.
- 문서를 새로 작성했다는 사실만으로 `approved` 또는 `implemented`로 변경하지 않는다.

## 4. 문서 검증

문서 작업 후 다음을 확인한다.

- Markdown 상대 링크 검사
- 코드 블록 시작·종료 균형 검사
- 후행 공백 검사
- 모델·데이터·평가 수치와 상태 태그 정합성 검사
- 예정 파일이 실제 링크로 작성되지 않았는지 검사
- `git diff --check`
- 요청 대상 외 변경 여부 확인

## 5. 문서 완료 기준

- 요청된 필수 목차와 표 필드가 모두 존재한다.
- 관련 기준 문서·ADR과 용어 및 수치가 일치한다.
- 깨진 상대 링크가 없다.
- 문서 상태와 본문 상태값이 실제 진행 수준에 적절하다.
- 존재하지 않는 예정 파일의 Markdown 링크가 없다.
- 중요한 결정에 ADR이 연결돼 있다.
- 문서 인덱스와 ADR 인덱스가 필요한 범위에서 갱신됐다.
- 변경 이력과 마지막 검토일이 반영됐다.
- 구현 상태를 완료로 잘못 표시한 항목이 없다.
