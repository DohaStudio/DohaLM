# DohaLM Codex 작업 절차

- 문서 상태: `review`
- 마지막 검토일: 2026-07-23
- 선행 문서: [저장소 지침](../AGENTS.md), [문서 지침](./AGENTS.md), [Definition of Ready](./31-definition-of-ready.md), [Definition of Done](./32-definition-of-done.md), [테스트 전략](./33-test-strategy.md)
- 후속 문서: 개별 작업 요청과 완료 보고
- 구현 전 필수 여부: Codex 작업 시 필수

## 1. 목적

- [확정] Codex가 저장소의 현재 상태와 작업 권한을 먼저 확인하고, 요청 범위 안에서 재현 가능하게 작업하도록 절차를 고정한다.
- [확정] 이 문서는 저장소와 하위 디렉터리의 `AGENTS.md`를 대체하지 않으며 함께 적용한다.
- [확정] 충돌 시 더 구체적인 하위 지침과 최신 사용자 요청을 우선하되, 안전 제한을 완화하지 않는다.

## 2. 작업 전 절차

1. [확정] 현재 경로를 확인한다.
2. [확정] 현재 브랜치가 요청된 브랜치인지 확인한다.
3. [확정] `git status --short`로 작업 트리 상태와 작업 시작 조건을 확인한다.
4. [확정] 저장소 루트 `AGENTS.md`를 읽는다.
5. [확정] 작업 경로에 적용되는 하위 `AGENTS.md`를 모두 읽는다.
6. [확정] 사용자 요청, 첨부 파일, 관련 README와 기준 문서를 끝까지 읽는다.
7. [확정] 관련 ADR을 읽고 기존 확정 사항과 미결정 사항을 구분한다.
8. [확정] 현재 구현과 파일 구조를 검색해 문서와 실제 상태의 차이를 확인한다.
9. [확정] 요청 범위·제외 범위와 생성·수정·금지 파일을 정리한다.
10. [확정] [Definition of Ready](./31-definition-of-ready.md)와 예정된 테스트 방법을 확인한다.

- [확정] 기존 변경은 사용자 소유로 간주하며, 요청 범위와 겹치면 임의로 덮어쓰지 않는다.

## 3. 작업 중 절차

- [확정] 최소 변경 원칙을 적용하고 요청 대상 외 파일을 수정하지 않는다.
- [확정] 문서의 `[확정]`, `[가정]`, `[검증 필요]`, `[후순위]`, `[제외]`를 사실 상태에 맞게 유지한다.
- [확정] 미확정 사항을 임의로 결정하지 않으며, 기존 사양을 변경해야 하면 관련 ADR을 검토한다.
- [확정] 코드와 문서를 동기화하되 구현되지 않은 기능, 실행하지 않은 테스트, 생성하지 않은 릴리스를 완료로 표현하지 않는다.
- [확정] 기존 테스트를 삭제하지 않고 실패를 숨기지 않는다.
- [확정] 모델·데이터·학습 수치는 기준 문서와 ADR을 대조하고 충돌을 임의로 해소하지 않는다.
- [확정] 설정값을 코드에 임의로 하드코딩하거나 근거 없는 수치·일정·성능을 만들지 않는다.
- [확정] 중간 검증을 수행하고 실패가 발견되면 영향 범위를 좁혀 기록한다.
- [확정] 대용량 데이터 처리나 장시간 모델 학습을 자동으로 실행하지 않는다.
- [확정] 60초 이상 작업이 이어질 때는 진행 상황과 다음 검증을 간단히 공유한다.
- [확정] 권한 확대, 파괴적 조작, 외부 공개가 필요하면 작업을 멈추고 사용자 승인을 요청한다.

## 4. 작업 후 절차

1. [확정] 변경 파일이 허용 목록과 일치하는지 확인한다.
2. [확정] `git diff --check`와 대상 파일 diff를 검토한다.
3. [확정] 관련 테스트 또는 정적 검사를 실행하고 미실행 항목과 이유를 구분한다.
4. [확정] Markdown 상대 링크를 검사한다.
5. [확정] 설정·수치·상태 태그와 문서 간 정합성을 검사한다.
6. [확정] 범위 밖에서 자신이 만든 변경은 안전하게 제거하되 기존 사용자 변경은 보존한다.
7. [확정] [Definition of Done](./32-definition-of-done.md) 충족 여부를 확인한다.
8. [확정] 사용자 지정 형식으로 변경, 검증, 미실행 사항을 사실대로 완료 보고한다.
9. [확정] 사용자의 명시적 요청이 없으면 `git add`, commit, push, merge, tag, release를 수행하지 않는다.

## 6. 즉시 중단하거나 승인을 요청할 조건

- [확정] 작업 트리에 예상하지 못한 변경이 있거나 사용자 변경과 요청 변경이 같은 구간에서 충돌한다.
- [확정] 필수 선행 문서가 존재하지 않는다.
- [확정] 서로 다른 문서의 확정 사양이 충돌한다.
- [확정] 데이터 라이선스가 불명확하거나 개인정보·비밀정보가 발견된다.
- [확정] 관련 테스트가 작업 전부터 실패하며 원인이 요청 범위와 분리되지 않는다.
- [확정] 요청 범위가 구현상 분리 불가능하고 허용 목록 밖 수정이 필요하다.
- [확정] 대용량 데이터 처리나 장시간 학습 실행이 필요하다.
- [확정] 현재 브랜치가 `main`이며 직접 수정이 요구된다.
- [확정] 삭제·강제 덮어쓰기·이력 재작성, 새 권한, 외부 공개 또는 리더보드 제출이 필요하다.
- [확정] 중단 시 전체 작업을 포기하지 않고 안전하게 수행한 확인 결과, 정확한 차단 원인과 사용자 결정이 필요한 사항을 보고한다.

## 7. Git과 파괴적 작업 안전

- [확정] 사용자의 명시적 요청 없이 stage, commit, push, merge, tag, release를 하지 않는다.
- [확정] commit을 요청받은 경우에도 diff를 검토하고 논리적 단위와 한국어 커밋 메시지를 먼저 확인한다.
- [확정] `git reset --hard`, 강제 checkout, 광범위 삭제 등 파괴적 명령은 명시적 승인 없이 사용하지 않는다.
- [확정] 기존 변경을 되돌리거나 자동 정리하지 않는다.

## 8. 핵심 미결정 사항

- [검증 필요] 구현 단계별 표준 명령과 테스트 ID 매핑
- [검증 필요] 자동화 가능한 완료 보고 생성 범위
- [검증 필요] 장시간 실행 시 진행 보고 주기와 승인 유효 범위
